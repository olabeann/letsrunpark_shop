## 이번 견적에서 제외하는 기능

예약권과 굿즈 혼합 결제, 상품 옵션, 할인·쿠폰, 고객의 상품·수량 부분 반품, 분할 배송, 자동 반품, 택배 API, 자동 알림, 비회원 구매, 해외 배송, 후기·문의·찜, 송장 엑셀 업로드와 양식 다운로드, 일괄 배송. 단, 주문 전체 반품에서 배송비를 차감하기 위한 PG 금액 부분취소는 포함한다.

예약관리시스템의 기존 업무 기능 변경 및 별도 관리자 신규 구축은 제외한다. 화면 디자인은 제공된 디자인 적용과 기존 관리자 수정 기준이며 신규 이미지 제작과 별도 디자인 시안 제작은 추가 산정한다.

## 산정에 적용할 동작 기준

한 주문에 여러 상품을 담고 한 번 결제하며 배송지는 한 곳으로 처리한다. 상품에는 옵션을 두지 않는다. 비로그인은 탐색만 허용하며 구매와 주문 조회는 기존 회원 인증을 사용한다.

취소는 주문 전체 단위로 처리한다. 고객의 허용 기한은 관리자 스토어 설정값을 따르며, 유효한 운송장번호가 저장되기 전이면 상품금액과 배송비를 포함한 실제 결제금액 전액을 PG 취소하고 재고를 복원한다. 취소 권한 관리자는 고객 취소 기한이 지난 뒤에도 운송장번호가 없는 주문을 취소할 수 있으며, 취소 사유 입력과 처리자·시각 기록이 필수다. 운송장번호 저장 성공 시 발송 완료로 전환하여 이후 고객 직접 취소와 일반 관리자 취소를 차단한다. 송장은 관리자가 직접 입력하고 배송조회는 외부 링크로 제공한다.

배송비 3,000원·취소 24시간·일반 반품 신청 14일은 시연 기본값이며 실제 값은 관리자 스토어 설정을 따른다. 주문 확정 시 당시 취소 가능 시간과 반품 신청 일수를 주문에 보존한다. 고객 직접 취소는 취소 기한 이내이면서 운송장번호가 저장되지 않은 주문에만 허용하고, 일반 반품 신청은 최초 운송장 등록 시각부터 주문에 보존된 일수 이내에 허용한다. 운송장번호 수정·삭제는 취소 권한을 복원하거나 반품 기한을 다시 시작하지 않고 이력으로 관리한다. 설정 변경은 새 주문부터 적용한다. 기한이 지난 불량·오배송 등 법정 예외는 고객센터 문의로 접수한다. 환불 담당자는 반품 상품의 실제 도착을 업무 절차로 수동 확인한 뒤 배송비 차감 여부와 금액을 최종 선택한다. 별도의 반품 도착 상태·확인 버튼·자동 검증은 범위에서 제외한다. 단순 변심은 왕복 배송비 차감, 불량·파손·오배송은 차감 없음을 기본값으로 제시한다. 기본값과 다른 처리 또는 차감액 변경 시 내부 사유 입력을 필수로 하고 최종 환불액·배송비 처리·사유·처리자·시각을 주문 이력에 보존한다. 환불 완료 상태를 되돌리거나 금액을 수정하는 기능은 제공하지 않는다. 오처리·추가 조정은 고객이 기존 고객센터 번호로 직접 문의하도록 하며 별도 CS 접수·채널 연결 기능은 범위에서 제외한다. 기본 견적은 주문당 정액 배송비와 단일 취소·반품 기한을 전제로 하며 조건부 무료배송이나 지역별 배송비는 포함하지 않는다.

반품 신청 후 고객이 상품을 발송하지 않아도 신청 상태는 자동 만료하지 않고 유지한다. 반품 운송장번호가 등록되기 전에는 고객이 직접 철회할 수 있고 철회 이력을 보존한다. 등록 후에는 직접 철회할 수 없으며 고객센터 문의로 처리한다. 철회 후 기존 신청 기한 안에는 재신청할 수 있다. 장기 미발송 건은 고객센터에서 전화로 확인하며 자동 만료 배치·자동 알림은 개발 범위에 포함하지 않는다.

고객은 환불 완료 전까지 반품 택배사와 운송장번호를 수정할 수 있다. 환불 완료 후에는 수정할 수 없으며 변경 이력 없이 최신 정보만 저장한다.

환불 완료 문자·알림톡은 제공하지 않는다. 환불 결과는 고객 주문 상세의 상태를 `환불 완료`로 변경해 안내한다.

고객의 반품 운송장번호가 등록되기 전에는 관리자 환불 완료 버튼을 비활성화해 표시하고, 고객 발송 전 안내는 반품 정보 박스 바깥에 둔다. 직접 API 요청도 거부한다. 운송장 등록 후 버튼을 활성화하며 담당자가 실제 상품 도착을 수동 확인한 뒤 환불한다.

반품 환불이 완료되어도 주문 수량은 판매 재고로 자동 복원하지 않는다. 검수 후 재판매 가능한 상품만 담당자가 상품 관리에서 별도로 재고를 조정한다.

반품 상품에 사용 흔적·고객 과실 훼손 등 상태 판단이 필요한 경우 관리자는 필수 반려 사유와 함께 `반품 반려`로 확정한다. 사유는 고객 주문 상세에 표시하며 고객 재신청은 막고 이후 조정은 기존 고객센터에서 처리한다. 별도 반품 도착 상태와 재발송 운송장 기능은 제공하지 않는다.

## 관리자 수정 기준

기존 관리자 안에 예약관리시스템과 커머스관리시스템 그룹을 둔다. 예약 그룹은 기존 5개 메뉴를 유지하고, 커머스 그룹에 굿즈 판매 현황과 온라인 스토어 운영을 배치한다.

표 제목과 내용의 열 가운데 정렬, 드롭다운 화살표 위치 조정, 표 아래 완료 문구 제거를 기본 화면 수정에 포함한다. 별도 관리자 구축으로 중복 산정하지 않는다.

출고는 주문별 송장 직접 입력 방식이다. 기본 택배사를 설정하고 주문별로 변경할 수 있다. 운송장번호는 공백·하이픈을 제거한 영문·숫자를 허용하며 주문 간 중복을 막지 않는다. 최초 등록 전 `등록 후 운송장 정보는 삭제할 수 없으며 수정만 가능합니다. 발송 완료로 처리하시겠습니까?`를 표시한다. 등록 후 삭제와 수정 이력은 제공하지 않는다.

상품 상세 편집 도구와 배송비·취소시간·반품기간·단순 변심 반품비 설정, PC·모바일 배너 관리는 기본 범위에 포함한다. 영상은 외부 주소 삽입만 지원하고 영상 파일 직접 업로드는 제외한다.

현재 화면은 업무 흐름 시연 자료다. 실제 인증·카드 승인·권한·서버 저장 연동이 완료된 것으로 산정하지 않는다. 시연 코드의 재사용 가능 범위는 개발사가 확인한다.
