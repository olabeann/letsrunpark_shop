# 화면별 개발 정책 오버레이 구현 프롬프트

아래 내용을 다른 프로젝트의 개발 요청 프롬프트로 그대로 사용할 수 있습니다.

---

## 프롬프트

현재 프로젝트에 **화면별 개발 정책 보기** 기능을 구현해줘.

### 목표

- macOS에서 `Option + Command + K`를 누르면 개발 정책 모드가 열린다.
- Windows와 Linux에서는 `Ctrl + Alt + K`를 보조 단축키로 제공한다.
- 정책 모드에서는 현재 화면의 주요 UI 영역을 점선 테두리나 반투명 강조선으로 표시한다.
- 강조된 영역을 클릭하면 해당 영역의 정책을 우측 패널에서 확인할 수 있어야 한다.
- 서비스의 기존 기능과 디자인은 유지하고, 정책 모드는 개발·검수용 보조 기능으로만 추가한다.

### 먼저 할 일

1. 현재 프로젝트의 화면, 컴포넌트, 데이터 구조, API 사용 방식을 분석한다.
2. 사용자 화면과 관리자 화면의 주요 정책 영역을 찾는다.
3. 기존 기획서, README, 기능명세서, API 문서가 있다면 함께 확인한다.
4. 실제 구현과 문서가 다르면 임의로 확정하지 말고 차이를 정책 패널에 명확히 표시한다.
5. 기존 코드를 최대한 재사용하고 전역 스타일이나 핵심 비즈니스 로직에 불필요한 영향을 주지 않는다.

### 정책 모드 UI

- 단축키를 누르면 화면 위에 정책 오버레이를 표시한다.
- 정책이 연결된 영역에는 점선 테두리와 작은 정책 라벨을 표시한다.
- 라벨에는 `정렬·표시 개수`, `표시 대상`, `이동 경로`, `입력·검증`, `상태 변경`처럼 정책의 성격을 짧게 적는다.
- 영역이나 라벨을 클릭하면 우측에 정책 상세 패널을 연다.
- 선택된 영역은 다른 영역보다 명확하게 강조한다.
- 우측 패널이 열려도 원래 화면의 위치와 구조를 확인할 수 있어야 한다.
- 패널에는 닫기 버튼을 제공한다.
- 같은 단축키를 다시 누르거나 `Escape`를 누르면 정책 모드를 종료한다.
- 모바일에서는 우측 패널 대신 하단 시트 형태로 표시한다.
- 정책 모드가 꺼져 있을 때는 관련 요소가 화면과 접근성 트리에 노출되지 않아야 한다.

### 우측 정책 패널 구성

각 정책은 다음 항목을 가능한 범위에서 포함한다.

- 정책 이름
- 한 줄 설명
- 적용 화면 및 대상 영역
- 표시 대상
- 제외 대상
- 정렬 기준
- 정렬 방향
- 동일 값일 때의 보조 정렬 기준
- 표시 개수
- 페이지네이션 또는 더보기 기준
- PC·태블릿·모바일 배치 기준
- 화면에 표시할 값
- 각 값의 의미
- 사용자 행동
- 이동 경로
- 입력 조건
- 검증 조건
- 빈 상태
- 로딩 상태
- 오류 상태
- 권한 조건
- 상태 변경 규칙
- FE 필수 구현사항
- BE 필수 구현사항
- 완료 조건 및 QA 기준
- 관련 기능명세 또는 정책 문서 위치

### 설명 작성 원칙

- API 주소나 쿼리 문자열만 적지 않는다.
- 기획자와 디자이너도 이해할 수 있는 자연어로 풀어서 작성한다.
- 필요한 경우 기술 정보는 자연어 설명 아래 보조 정보로 제공한다.
- 무엇을 보여주는지, 어떤 순서인지, 몇 개를 보여주는지, 어떤 경우 제외되는지가 바로 이해되어야 한다.
- FE와 BE의 책임을 구분한다.
- 값이 어디에서 만들어지고 누가 최종 검증하는지 명시한다.
- 서버 시간이 필요한 값은 사용자 기기 시간이 아니라 서버 시간을 사용한다고 명시한다.
- 불명확하거나 아직 구현되지 않은 내용은 `미확정`, `연동 필요`, `현재 미구현`으로 표시한다.
- 실제로 제공하지 않는 기능을 구현된 것처럼 작성하지 않는다.

### 설명 예시

나쁜 설명:

```text
GET /products?status=displayable&sort=updatedAt,desc&page=1&size=24
```

좋은 설명:

> 고객에게 표시할 수 있는 상품만 조회해 가장 최근에 등록하거나 수정한 상품부터 전달합니다. 한 번에 최대 24개를 제공하며, 판매 중지 상품은 제외하고 품절 상품은 목록에 포함합니다. 상품의 수정 시각은 서버가 기록한 값을 기준으로 사용합니다.

### 상품 목록 정책 예시

- 표시 대상: 판매 중 또는 품절 상품
- 제외 대상: 판매 중지 상품
- 정렬 기준: 최근 등록·수정 시각 내림차순
- 보조 정렬: 수정 시각이 같으면 상품 ID 내림차순
- 표시 개수: 페이지당 최대 24개
- 배치 기준: PC 4열, 태블릿 2열, 모바일 1열
- 카드 정보: 대표 이미지, 판매 상태, 상품명, 판매가
- FE 필수: 서버가 전달한 순서를 유지하고 품절 상품의 구매를 차단한다.
- BE 필수: 상품 등록·수정·판매 상태 변경 시 수정 시각을 서버 기준으로 갱신하고 최근 수정순으로 결과를 전달한다.

### 구현 구조

- 정책 데이터와 화면 렌더링 코드를 분리한다.
- 정책은 배열 또는 객체 형태의 설정 데이터로 관리한다.
- 각 정책은 고유 ID와 연결할 CSS 선택자를 가진다.
- 특정 요소가 없는 화면에서는 오류 없이 해당 정책 표시만 생략한다.
- SPA의 화면 전환이나 DOM 변경 후에도 현재 화면의 정책 영역을 다시 탐색한다.
- 리사이즈와 스크롤 시 강조 영역의 위치를 다시 계산한다.
- 오버레이가 기존 버튼, 입력창, 링크 동작을 영구적으로 막지 않게 한다.
- 사용자 개인정보, 토큰, 주문 상세값 등 실제 민감 정보는 정책 패널에 출력하지 않는다.
- 운영 환경에서 숨길 필요가 있다면 환경 변수 또는 개발자 플래그로 활성화 여부를 제어할 수 있게 한다.

### 접근성

- 우측 패널에 적절한 `dialog` 또는 `complementary` 의미를 부여한다.
- 키보드만으로 정책 영역 선택, 패널 이동, 닫기가 가능해야 한다.
- 포커스 표시를 제공한다.
- 색상만으로 선택 상태를 구분하지 않는다.
- 닫을 때 기존 포커스 위치로 돌아간다.

### 완료 후

1. 추가하거나 수정한 파일을 알려준다.
2. 화면별로 어떤 정책 영역을 등록했는지 정리한다.
3. 단축키, 닫기, 스크롤, 리사이즈, 모바일 표시를 검증한다.
4. 기존 기능에 회귀가 없는지 확인한다.
5. 관련 README, 기능명세서, 개발전달서가 있다면 실제 구현과 동일하게 갱신한다.
6. 문서나 코드에 이전 정책이 남아 있는지 전체 검색한다.
7. 보관용 `archive` 문서는 현재 문서와 구분하고, 별도 요청이 없으면 수정하지 않는다.

### 프로젝트별 추가 입력

프로젝트별로 더 정확한 결과가 필요하면 아래 내용을 채워서 프롬프트 마지막에 추가한다.

```text
이번 프로젝트에서 특히 확인할 영역은 다음과 같다:
- [화면 또는 기능 1]
- [화면 또는 기능 2]
- [화면 또는 기능 3]

정책 화면의 시각적 참고 이미지는 첨부한 이미지와 동일한 정보 구조를 따르되,
기존 프로젝트의 색상·폰트·간격 체계를 유지한다.
```
