## 추천 확인 순서

1. 사용자 홈 → 상품 상세에서 수량 선택 → **바로 구매**.
2. 시연 로그인 → 주문·결제 화면에서 테스트 정보 입력 → 거래조건·개인정보 필수 동의 2종 → **결제하기**.
3. 주문 완료 → 주문 조회 → 주문 상세에서 결제·배송 정보 확인.
4. 같은 브라우저에서 관리자 접속 → 배송 처리에서 택배사와 송장번호 입력 → 주문별 발송 완료.
5. 사용자 주문 상세를 다시 열어 배송 상태와 송장번호 확인.
6. 관리자 **온라인 스토어 운영**에서 상품·재고·상세 소개 편집 후 사용자 상품 상세 확인.

반품·환불 흐름은 주문 조회의 배송 완료 예시 주문에서 확인할 수 있습니다. 고객은 주문 전체 반품을 먼저 신청하고, 안내된 주소로 착불 발송한 뒤 주문 상세에서 반품 운송장을 등록합니다. 고객에게 반품 발송 대기·반품 확인 중·환불 완료·관리자 예외 환불 상태를 표시합니다. 관리자는 별도 수거 예약 없이 도착 상품과 운송장을 확인하고, 반품 사유에 맞게 추천된 배송비 차감 여부·고객 안내를 확인한 뒤 환불을 완료합니다.

## 로컬 실행

HTML·CSS·JavaScript로 구성되어 있으며 패키지 설치나 빌드 없이 실행할 수 있습니다. Python 3가 설치된 환경에서 저장소 루트에서 실행하세요.

```sh
python3 -m http.server 8000 --directory dist
```

- [로컬 사용자 화면](http://localhost:8000/index.html)
- [로컬 상품 상세](http://localhost:8000/product.html?id=1)
- [로컬 주문 조회](http://localhost:8000/orders.html)
- [로컬 관리자 화면](http://localhost:8000/admin.html)

시연 링크의 도메인을 `http://localhost:8000`으로 바꾸면 동일한 경로를 확인할 수 있습니다. GitHub에서 `dist/index.html` 파일을 클릭하면 소스가 표시되므로, 화면은 시연 사이트 또는 로컬 서버에서 확인하세요.

## 시연 데이터와 구현 범위

- 상품·장바구니·주문·스토어 설정은 브라우저의 `localStorage`, 결제 진행 정보는 `sessionStorage`에 저장됩니다.
- 사용자·관리자 데이터 확인은 같은 브라우저의 같은 사이트 주소에서 진행하세요. 배포 사이트와 로컬 서버의 데이터는 각각 저장됩니다.
- 실제 회원 인증, 카드 결제, 서버 주문·재고 연동을 완료한 운영 서비스가 아닙니다. 결제 완료와 취소 처리는 시연 동작입니다.
- 관리자 화면에는 서버 기반 관리자 인증이 구현되어 있지 않습니다.

각 HTML에는 해당 페이지의 본문과 필요한 대화상자만 있습니다. 각 페이지는 전용 JavaScript를 로드하며, 헤더·푸터·관리자 메뉴는 `store-layout.js`·`admin-layout.js`에서 공유합니다. 데이터, 로그인, 장바구니와 재사용 위젯만 공통 파일에 두었습니다. `app.js`, `store-flow.js`, `admin-ui.js`, `admin-policy-v2.js`는 페이지별 파일로 통합·이관 후 제거했습니다. 별도 빌드 없이 해당 HTML과 JavaScript를 직접 수정합니다. 시연 로그인은 같은 탭의 세션에 유지됩니다.

구조와 주요 흐름 검사는 `node --test tests/*.test.cjs`로 실행합니다. 페이지별 본문 분리, 스크립트 경로·선언 충돌, 결제 진행 데이터 전달과 송장 등록 규칙을 검사합니다.

## 재고 관리

결제 시 차감과 발송 전 주문 취소 시 복원도 같은 이력에 기록됩니다. 반품 환불은 기존 정책대로 자동 복원하지 않으며 검수 후 관리자가 사유와 함께 입고합니다. 시연 데이터는 브라우저 저장소에 보관됩니다. 실제 운영의 여러 사용자 동시 처리는 서버의 재고 트랜잭션과 인증된 처리자 기록이 필요합니다.


## 관리자 주문 상태 구분

상품 판매 현황의 결제·환불 열은 결제 완료 / 환불 완료 / 전액 환불 완료만 표시합니다. 반품 신청는 환불 완료 전까지 결제 완료를 유지합니다. 배송 상태 열은 배송 준비 중 / 발송 완료 / 배송 대상 아님으로 구분하며 반품·환불 이후에도 기존 발송 이력을 유지합니다. 발송 전 전체 취소는 전액 환불 완료와 배송 대상 아님으로 표시합니다. 배송비 차감 환불은 전액 환불로 표시하지 않습니다.

반품 상태 열과 검색 필터는 해당 없음 / 반품 신청 완료 / 반품 처리 완료를 제공합니다. 결제·환불·배송·반품 필터를 함께 선택하면 AND 조건으로 조회합니다. 반품 상태는 목록과 상세에서 동일하게 표시하며, 주문 취소·반품 환불·관리자 예외 환불 유형 및 금액은 상세의 환불 내역에서 확인합니다. 예외 환불에는 반품 신청 정보가 표시되지 않습니다. 결제·환불 필터는 결제 완료 / 환불 완료로 조회하며 환불 완료에는 모든 환불 유형을 포함합니다. 현재 시연에는 비동기 환불 처리 중 상태가 없습니다.

상품 판매 현황에는 반품 상태 열과 필터를 제공하며 발송 송장 열은 표시하지 않습니다. 택배사·송장번호·배송조회는 주문 상세의 발송 송장 정보에서 읽기 전용으로 확인하고 등록·수정은 배송 처리에서 진행합니다.

### 구매 전 확인사항 작성

스토어 운영 설정의 구매 전 확인사항은 일반 텍스트로 작성합니다. 결제 화면에는 입력한 문구와 줄바꿈·빈 줄을 그대로 표시합니다. 자동 말머리 기호를 붙이지 않으며, 필요한 기호는 직접 입력합니다. 변수나 설정값 자동 치환을 지원하지 않습니다. 배송비·취소 시간·반품 기간을 변경하면 안내 문구도 직접 수정합니다. 기존에 저장한 변수 문구는 현재 설정값을 사용해 일반 텍스트로 한 번 전환하고, 기존 주문의 동의 내역은 보존합니다.


### 주문 취소 · 환불 버튼 정책 (개발 인계)

발송 전·후의 기준은 최초 발송 운송장 등록 여부입니다. 반품 운송장은 별도 정보입니다. 아래 현재 버튼명은 실제 화면 기준이며 권장 명칭은 제안 단계입니다.

| 현재 버튼 / 권장 명칭 | 노출·실행 조건 | 처리 결과 | 재고 |
| --- | --- | --- | --- |
| 관리자 주문 취소 / 발송 전 주문 취소 | 출고 대기·발송 송장 없음. 고객 취소 시간 제한 미적용. 처리 사유 필수 | 전액 환불 완료 / 배송 대상 아님 / 반품 해당 없음 | 차감된 재고만 한 번 복원 |
| 관리자 예외 환불 / 발송 후 예외 환불 | 발송 송장 있음·반품 상태 없음·취소/환불 미완료. 반품 송장 불필요. 사유 필수 | 전액 또는 배송비 차감 환불 / 발송 완료 / 반품 해당 없음 | 자동 복원 없음 |
| 반품처리(환불) / 반품 환불 처리 | 반품 신청 완료 시 반품 처리 영역에 노출. 반품 송장 미등록 시 비활성화와 대기 안내, 등록 후 활성화. 실제 상품 도착 확인 후 확정 | 전액 또는 배송비 차감 환불 / 발송 완료 / 반품 처리 완료 | 자동 복원 없음 |

반품 환불은 단순 변심 시 설정 반품비 차감, 불량·파손·오배송은 전액 환불이 기본입니다. 기본 배송비 처리 변경 사유는 필수입니다. 발송 후 예외 환불은 반품 절차 없이 관리자가 직접 처리하는 별도 유형입니다. 반품 신청만으로 환불되지 않으며, 반품 송장 미등록 상태에는 반품처리(환불) 버튼을 비활성화하고 운송장 등록 대기 안내를 표시합니다. 매출·정산의 읽기 전용 상세는 닫기만 제공합니다.

고객의 **주문 전체 취소**는 출고 대기·발송 송장 없음·반품 상태 없음·주문 취소 마감 전 조건을 모두 만족해야 합니다. **전체 반품 신청**은 최초 발송 송장 등록 후 주문의 반품 기간 이내이며 기존 반품 상태·반려 이력이 없어야 합니다. **반품 신청 철회**는 신청 완료·반품 송장 미등록 상태에만 가능하며 결제·재고를 변경하지 않습니다.

주문 취소·반품 환불·예외 환불 모달은 같은 너비, 주문번호 헤더, 처리 안내, 금액 요약, 입력란과 하단 버튼 형식을 사용합니다. 최종 실행명은 취소 확정 / 환불 확정으로 구분합니다. 닫기·편집 취소는 주문 처리 액션이 아닙니다.

서버 구현 시 권한·최신 상태·발송/반품 송장·금액을 실행 시 재검증하고 중복 처리를 방지합니다. 환불 성공 후 상태와 재고 반영을 일관되게 확정하며 처리자·시각·사유·금액·차감액·유형을 기록합니다. 이 항목은 서버 개발 요구사항이며 시연의 브라우저 저장 구현과 구분합니다. 상품·수량 일부 취소/반품은 지원하지 않습니다. 취소·환불 완료 후 재처리를 막고, 결제·배송·반품 상태와 환불 유형은 별도로 관리합니다.

### 관리자 로그인 화면

관리자 로그인은 `dist/admin-login.html`에서 별도 제공하며, 전용 스타일과 동작은 `admin-login.css`, `admin-login.js`에 있습니다. `admin-auth.js`는 예약 프로젝트와 같은 세션 키를 사용합니다. 로그인 전 관리자 페이지에 접근하면 로그인 화면으로 이동하고, 로그인 완료 후 원래 페이지로 돌아갑니다. 로그아웃도 스토어 로그인 화면으로 연결됩니다. 아이디·비밀번호 확인 후 OTP 인증을 완료해야 로그인됩니다. OTP 선택 인증·미등록 계정은 비밀번호만으로 로그인하며, 필수 인증 또는 등록된 계정은 OTP를 확인합니다. OTP 등록·초기화는 계정·권한의 계정 정보에서만 진행하고 로그인 인증은 등록 상태를 변경하지 않습니다. 시연용 OTP 번호는 `123456`이며, 실제 인증은 서버 연동이 필요합니다.

계정 · 권한 화면은 `dist/admin-accounts.html`과 전용 CSS·JavaScript에서 직접 표시합니다. iframe이나 원격 페이지를 불러오지 않으며, 예약 프로젝트와 동일한 `letsrunParkDepartmentAccountsV3` 저장 형식을 사용합니다. 동일 출처에서는 계정 설정을 공유합니다.

반품 불가 판단과 고객 안내는 CS에서 처리합니다. 관리자 반품 반려 버튼과 신규 반려 상태 변경은 제공하지 않습니다. CS 협의 전에는 환불 완료 처리하지 않으며, 기존 반려 이력은 주문 목록 전체 조회와 상세에서 유지합니다.

### 개발 확인용 주문 상태 예시

공통 `dist/order-demo-data.js`는 UI가 달라지는 8가지 예시만 제공합니다. 반품 사유만 다른 주문은 중복 생성하지 않으며 전액/차감 선택은 환불 모달에서 전환해 확인합니다. 환불 완료 결과는 결제 배지와 차감 표시가 달라 두 가지를 유지합니다.

| 주문번호 (G-DEMO- 접두사) | UI 차이 |
| --- | --- |
| RETURN-READY-CHANGE | 반품처리(환불) 버튼 활성 · 환불 모달 |
| RETURN-WAIT-CHANGE | 반품처리(환불) 버튼 비활성 · 송장 등록 대기 안내 |
| RETURN-DONE-FULL | 전액 환불 완료 배지 · 차감 없음 · 처리 이력 |
| RETURN-DONE-DEDUCT | 환불 완료 배지 · 배송비 차감액 · 처리 이력 |
| SHIP-PENDING | 배송 준비 · 관리자 주문 취소 버튼 |
| SHIP-SENT | 발송 완료 · 관리자 예외 환불 버튼 |
| CANCELLED | 배송 대상 아님 · 주문 취소 환불 내역 |
| EXCEPTION-FULL | 반품 해당 없음 · 예외 환불 사유 및 내역 |

기존 브라우저에서도 더 이상 필요 없는 예시 4건(RETURN-READY-DEFECT, RETURN-WAIT-WRONG, EXCEPTION-DEDUCT, RETURN-LEGACY-REJECT)은 위 코드가 만든 `demo: true` 주문만 제거합니다. 실제 주문과 기존 반려 이력은 수정하지 않습니다. 남은 예시는 설명용 이름만 정리하며 직접 처리한 결과를 초기화하지 않습니다. 모두 가상 주문으로 재고 차감은 적용하지 않습니다.

[활성 반품 버튼 예시 바로 열기](https://olabeann.github.io/letsrunpark_shop/admin.html?order=G-DEMO-RETURN-READY-CHANGE). 목록에서 **G-DEMO**를 검색하면 확인할 수 있습니다. 가상 송장을 사용하며 날짜는 최초 생성 시점으로 유지합니다.

### 굿즈 할인 관리 (고객사 확인 전 가정 정책)

- 관리자 **온라인 스토어 운영 → 할인 관리** 탭(`admin-discounts.html`)에서 할인 목록 및 등록·수정·삭제를 제공합니다. 기존 상품관리와 동일한 목록 테이블·등록/수정 팝업 및 공통 관리자 스타일을 사용하며, 예약 할인관리의 입력 항목을 굿즈에 맞췄습니다.
- 별도 발급 없이 주문서에서 할인 1종을 선택합니다. 정액·정률은 상품 1개당 적용하며 정률 할인액은 원 미만 버림입니다.
- 최대 수량은 **할인별 계정당 누적** 제한입니다. 할인액이 큰 상품부터 남은 수량까지 적용하며, 재주문은 기존 사용량을 차감하고 전체 취소·반품 환불 완료 시 복원합니다. 기간 변경으로 사용량을 초기화하지 않습니다. 브라우저 미리보기 계정 ID를 새 주문에 저장하며, 계정 ID가 없는 기존 주문은 합산하지 않습니다. 운영 시 서버 회원 ID 및 동시 결제 검증이 필요합니다.
- 한국 시간 시작일 00:00~종료일 23:59:59까지 적용합니다. 결제 직전에 변경·종료 여부를 다시 확인합니다.
- 전체 굿즈는 신규 상품도 자동 포함합니다. 체크 해제 시 개별 굿즈를 선택합니다.
- 상품 할인은 배송비에 영향을 주지 않습니다. 현재 고정 배송비 정책을 유지하며 할인 전 상품금액을 배송비 계산에 전달합니다. 별도 무료배송 기준 설정은 추가하지 않습니다.
- 주문에 할인 정책·상품별 적용 수량·금액을 저장합니다. 할인 수정/삭제 후에도 주문 내역은 유지하며 취소·환불·정산은 실결제금액 기준입니다.
- 할인은 브라우저 `goodsDiscountsV1`에 저장하는 시연 구현입니다. 실제 운영에는 서버의 할인 검증 및 주문 저장 연동이 필요합니다.

사용자 할인 UI: 상품 상세에서 선택 수량 기준 할인 가능액을 안내하고, 주문서에서는 할인 1종 선택 후 상품별 적용 수량과 할인액을 표시합니다. 주문 상세는 결제 당시 저장된 할인 내역을 표시합니다.
