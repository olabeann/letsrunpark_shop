# 말마프렌즈 온라인 스토어 개발 전달서 v2.2

전체 기능과 구현 기준을 함께 확인하는 개발 문서

기획 개정안 v2.2  |  2026년 9월 18일

회원의 굿즈 구매부터 관리자 출고와 상품 운영까지 총 26개 기능을 이 문서에 모았다. 기능표에서 전체 개발 범위를 확인하고 기능명을 클릭해 상세 동작으로 이동한다. 뒤쪽에는 공통 정책과 권한, 주문 상태, 데이터와 연동, 미확정 결정 항목, 검수 시나리오를 수록했다.

관리자는 하나의 프로그램 안에서 예약관리시스템과 커머스관리시스템으로 나뉜다. 이번 개발 대상은 커머스 영역이다. 실제 회원 인증과 PG 및 서버 저장 연동은 구현해야 하며 시연 화면의 동작만으로 완료를 판단하지 않는다.

## 공통 구현 기준

회원과 관리자 권한은 서버에서 검사한다. 금액과 재고는 결제 직전에 재검증하고 주문 당시 값을 보존한다. 승인 취소 발송 요청은 중복 실행과 동시 요청에도 한 번만 반영한다. 로딩 오류 빈 결과를 구분하고 입력 오류는 해당 위치에 표시한다.

관리자 표의 제목과 내용은 열 가운데에 정렬한다. 드롭다운 화살표는 오른쪽 세로 중앙에 배치한다. 표 아래 작업 완료 문구는 제거하고 변경된 상태로 결과를 확인한다. 송장 입력의 공통 택배사 중심 UI는 추가 반영 제안이다.

배송비 3,000원과 취소 24시간은 확정 정책이 아니다. DEC 항목을 확인한 뒤 개발한다. 부분 취소 분할 배송 자동 반품 택배 API 자동 알림 비회원 구매는 이번 범위에서 제외한다.

## 기능별 개발 동작 1

### FN-001 스토어 진입

연결  SCR-U-001 | 견적 v9 포함

시작  기존 렛츠런플레이 메뉴 또는 고객사 소개 페이지에서 스토어 링크를 선택한다.

개발 동작  스토어 목록으로 이동한다. 브라우저 뒤로가기를 지원한다. 외부 소개 콘텐츠 제작은 고객사 제공 범위다.

검증과 예외  없는 상품 주소로 진입하면 안내와 목록 복귀를 제공한다. 최종 도메인과 연결 위치는 DEC-008에서 확정한다.

현재 시연  메인 페이지와 기존 서비스 연결 링크가 있다. 실제 기존 사이트 메뉴 연결은 확인하지 않았다.

검수  TC-001 링크 진입 후 상품 목록이 보이고, 잘못된 상품 주소는 안내한다.

### FN-002 상품 목록

연결  SCR-U-001 | 견적 v9 포함

시작  메인 진입 또는 목록 복귀 시 최신 판매 상품을 조회한다.

개발 동작  대표 이미지·상품명·가격을 노출한다. 품절은 구매 불가 상태로 표시한다. 노출 순서가 같으면 상품 ID로 정렬한다.

검증과 예외  목록 필터를 유지한다면 전체·판매 중·품절에 실제 적용한다. 미노출 상품 상세 접근도 차단한다. 노출 순서는 FN-025에서 개발한다.

현재 시연  판매 중과 품절을 노출하고 hidden은 제외한다. 활성 렌더 함수는 화면 판매 상태 필터 값을 사용하지 않는다.

검수  TC-002 미노출 상품은 목록·상세에서 보이지 않고, 필터 및 정렬 결과가 일치한다.

### FN-003 상품 상세와 안내

연결  SCR-U-002 | 기본 상세는 견적 포함 상세 에디터는 범위 재확인

시작  목록에서 상품을 선택하거나 상품 URL로 직접 진입한다.

개발 동작  대표 이미지와 상품정보, 구매 영역, 상세 콘텐츠, 배송·취소 안내 순으로 구성한다. HTML은 서버에서도 허용 요소만 저장·출력한다.

검증과 예외  품절이면 수량·선택 합계는 숨기고 단일 품절 버튼을 표시한다. 모바일 하단 구매 영역은 개선 제안이며 구현 완료가 아니다.

현재 시연  대표 이미지·요약·가격·상세 콘텐츠·고정 배송비·취소 안내를 표시한다.

검수  TC-003 판매·품절·잘못된 상품 ID 각각에서 올바른 콘텐츠와 구매 가능 상태를 표시한다.

## 기능별 개발 동작 2

### FN-004 구매 수량과 바로 구매

연결  SCR-U-002 | 견적 v9 포함 수량 제한값은 미확정

시작  판매 중이고 가용 재고가 1개 이상인 상품에서 수량 변경 또는 바로 구매를 선택한다.

개발 동작  정수 1개부터 가용 재고와 확정된 구매 제한 중 작은 값까지 선택한다. 바로 구매는 해당 상품만 주문서에 넣고 기존 장바구니를 유지한다.

검증과 예외  담기에서는 장바구니 기존 수량을 더해 상한을 계산한다. 바로 구매는 별도 주문 수량 기준이다. 재고 변경 시 해당 상품에 오류를 표시한다.

현재 시연  활성 상세 수량 증가와 장바구니 담기는 재고 상한이 없다. 결제 제출 시 검사한다.

검수  TC-004 재고 9개일 때 10개 선택·합산 담기를 막고, 바로 구매 후 기존 장바구니가 유지된다.

### FN-005 기존 회원 로그인 연동

연결  SCR-U-003 | 견적 v9 기존 로그인 재사용

시작  비로그인 사용자가 담기·바로 구매·장바구니·주문 조회를 실행한다.

개발 동작  기존 회원 인증을 호출하고 서버가 세션과 회원 ID를 확인한다. 성공하면 선택 상품·수량과 원래 행동을 복원한다.

검증과 예외  로그인 중단·실패 시 주문을 생성하지 않는다. 기존 서비스 제공 로그인 수단을 DEC-007에서 확인한다. 노출 버튼이 연동 확정을 의미하지 않는다.

현재 시연  네이버·카카오 버튼은 메모리의 로그인 플래그를 바꾼다. OAuth·회원 식별·실제 세션은 없다.

검수  TC-005 로그인 실패 시 구매 진행이 없고, 성공 시 원래 동작을 이어간다. TC-010 타인 주문 접근을 거부한다.

### FN-006 복수 상품 장바구니

연결  SCR-U-004 | 견적 v9 포함

시작  회원이 상품을 담거나 장바구니 패널을 연다.

개발 동작  같은 상품은 한 행으로 합산한다. 수량 변경·삭제와 상품합계·주문당 배송비·총액을 표시한다. 재고를 선점하지 않는다.

검증과 예외  품절·미노출·가격·재고 변경을 열기와 주문서 이동 시 다시 검사한다. 빈 장바구니는 결제 불가다. 저장 기간·기기 간 공유는 DEC-012에서 결정한다.

현재 시연  localStorage에 상품 ID와 수량을 저장한다. 수량·삭제·합계가 있으며 빈 장바구니 버튼은 숨긴다.

검수  TC-006 서로 다른 2개 상품을 함께 주문하고, 삭제·수량·배송비가 즉시 합계에 반영된다.

### FN-007 주문자와 수령인 입력

연결  SCR-U-005 | 견적 v9 포함

시작  장바구니 또는 바로 구매에서 주문서로 이동한다.

개발 동작  주문자 이름·연락처와 수령인 이름·연락처를 구분한다. 주문자와 동일 체크로 복사한다. 우편번호·기본주소는 필수, 상세주소·배송메모는 선택 제안이다.

검증과 예외  공백 이름·잘못된 전화번호·누락 필드를 결제 전에 검사하고 입력 위치로 이동한다. 최대 길이와 허용 연락처 형식은 DEC-010에서 확정한다.

현재 시연  이름·전화·우편번호·기본주소·필수 상세주소·배송메모를 입력한다. 별도 수령인 입력란은 없다.

검수  TC-007 다른 수령인을 입력해 저장·조회할 수 있고, 상세주소가 없어도 주문서 검증을 통과한다.

### FN-008 주소 검색과 구매 동의

연결  SCR-U-005 | 주소 검색은 시연 반영 동의 문구는 확정 필요

시작  주소 검색 버튼 선택 또는 필수 구매 안내 체크를 변경한다.

개발 동작  전체 상품을 노출 순서 기준으로 조회하고 상품명·판매 상태 검색을 제공한다. 판매 중지 상품도 관리 화면에서는 확인할 수 있다.

검증과 예외  0재고는 품절로 표시한다. 판매 상태와 재고 충돌은 저장·조회에서 같은 기준을 적용한다. 목록 페이지 분할은 DEC-009에서 결정한다.

현재 시연  상품명·판매 상태 필터와 대표 이미지·가격·재고·상태·수정 버튼이 있다.

검수  TC-025 판매·품절·판매 중지 각각 검색되며 사용자 노출 결과와 일치한다.

### FN-023 상품 상세 콘텐츠 편집

검증과 예외  비허용 스크립트·이벤트·URL을 제거한다. 영상 파일 직접 업로드는 현재 없으며 추가 범위다. 미리보기는 현재 상세 콘텐츠만 보여준다. 전체 모바일 상세 미리보기는 개선안이다.

현재 시연  본문·제목·서식·목록·링크·이미지·동영상·실행 취소·확대·상세 콘텐츠 미리보기가 있다.

검수  TC-027 정상 콘텐츠가 사용자 상세에 같게 표시되고 비허용 코드·URL은 실행되지 않는다. 저장 실패 시 작성 내용이 남는다.

검증과 예외  오래 열린 편집창이 결제 차감 재고를 덮어쓰지 않도록 버전을 검사한다. 재입고 자동 판매 재개는 DEC-013에서 확정한다. 수동 품절과 재고 0 품절의 원인을 구분하는 제안이다.

현재 시연  상품 수정에서 재고를 덮어쓴다. 0재고+판매 중 저장 시 품절로 변경한다. 조정 사유·변경 이력은 없다.

검수  TC-028 결제 후 오래된 편집창 저장은 충돌 안내한다. 재고 조정 이력과 실제 수량이 일치한다.

### FN-026 배송비와 취소 정책 설정

검증과 예외  기존 주문 금액·취소기한은 보존한다. 결제 직전 설정 변경 시 새 금액 재확인을 받는다. 주간 마감·발송 요일은 안내 문구이며 자동 스케줄러가 아니다.

## 중복과 동시 처리 및 복구

결제 요청과 취소·출고 작업에 고유 요청 키를 부여하고 중복 요청은 기존 결과를 반환한다. PG 거래번호와 주문 연결은 유일하게 관리한다. 중복 승인 콜백과 재시도는 재고를 추가 차감하지 않는다.

마지막 재고를 두 회원이 동시에 결제하는 경우 둘 다 승인된 채 한 주문을 잃지 않도록 임시 재고 예약과 만료·해제 또는 동등한 방식을 설계한다. 예약 기간·외부 승인 초과 시 보상 취소는 개발·PG 검토로 결정한다. 확인 중 결제는 조회 및 대사 후 복구하고 미해결은 운영 담당자에게 표시한다.

취소와 발송은 동일 주문에 대해 동시에 확정할 수 없다. 주문 버전 또는 서버 잠금으로 한 처리만 성공시킨다. 수동 재고 수정도 버전 검사로 결제 차감을 덮어쓰지 않는다.

## 오류 응답과 화면 처리 제안

오류는 code·사용자 메시지·fieldErrors 또는 상품별 오류·재시도 가능 여부·서버 요청 ID를 반환하는 제안이다. 인증 만료는 로그인 복귀, 권한 없음은 조회 불가, 재고 부족은 상품행, 가격·정책 변경은 새 총액 재확인, 버전 충돌은 최신값 확인, PG 결과 불명은 확인 중 상태로 연결한다.

회원·PG·기존 관리자 연동 자료 확인 → 정책·추가 범위 결정 → 데이터·API·처리 보장 설계 → 사용자 및 관리자 개발 → 시나리오 검수 → 운영 가이드 및 복구 담당 인계 → 합의된 오픈 절차 진행. 자동 알림 서비스 추가를 전제로 하지 않으며 운영 오류 확인 수단은 기존 관리자 또는 운영 도구와 연결해 정한다.

## 이번 개정의 핵심

화면 구조와 기능 및 검수 ID를 연결했다. 결제·배송·환불 상태를 분리하고, 미확정 배송비와 취소시간을 시연 기본값으로 명시했다. 견적에 포함된 노출순서의 구현 누락, 로그인과 본인 주문 권한 부재, 별도 수령인 입력 부재, 재고상한 누락, 관리자 취소의 시간 예외를 드러냈다.

상세 에디터·정책 설정 UI 등 시연 추가 기능은 개발 범위 재합의 대상으로 표시했다. 고정 저장·편집내용 보존·모바일 구매 영역·전체 상품 미리보기는 현재 구현 사실과 개선안을 분리했다. 기존 파일은 덮어쓰지 않고 v2.2로 생성했다.

## 최신 관리자 수정 지시 반영

스트로크 최소화 디자인 재구성 대화의 사용자 지시와 현재 admin.html을 확인했다. 예약관리시스템 아래에 예약·티켓, 프로그램·회차, 운영일 관리, 매출·정산, 계정·권한을 배치하고, 커머스관리시스템 아래에 굿즈 판매 현황과 온라인 스토어 운영을 배치한다. 표 가운데 정렬·드롭다운 화살표 위치·표 아래 완료 문구 제거를 반영 기준에 포함했다. 송장 엑셀 업로드와 양식 다운로드는 최종 지시로 제외하고 직접 입력 및 선택 주문 일괄 발송을 유지한다. 목록 CSV 내려받기는 현재 화면에 남아 있어 별도로 유지한다. 상단 공통 택배사 중심의 단순화는 다른 대화의 제안으로, 현재 행별 선택창과 구분해 추가 반영 대상으로 표시했다.

## 확인 범위의 한계

이 문서는 저장소의 문서와 코드를 정적으로 대조한 기획 자료다. 고객사 원문 메일·실제 회원 서버·PG 설정·운영 DB·관리자 권한체계는 제공되지 않았다. 기존 명세가 메일 요구로 분류한 항목은 원문 요구를 재검증한 것으로 간주하지 않는다. 외부 URL과 서비스 이용 조건을 재검증하지 않았다.
