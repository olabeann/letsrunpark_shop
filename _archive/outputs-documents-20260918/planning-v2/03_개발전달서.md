## H01 서비스 소개와 개발자가 알아야 할 범위

이 서비스는 렛츠런플레이 회원이 말마프렌즈 굿즈를 구매하고, 기존 운영 관리자가 주 1회 출고 업무를 수행하는 온라인 스토어다. 체험 예약의 이용일·시간·회차 선택을 사용하지 않으며, 상품과 수량만 선택한다. 여러 굿즈는 한 주문·한 결제·한 배송지로 구매한다.

기존 회원·관리자 계정·PG·인프라를 재사용하는 것이 견적의 전제다. 실제 재사용 가능 범위는 아직 검증되지 않았다. 구현된 정적 화면은 업무 흐름 참고 자료이며 실제 운영 백엔드가 아니다.

## 자료 읽는 순서

IA에서 화면과 이동을 이해한 뒤 기능명세서 F01부터 F26의 동작을 확인한다. 이 전달서 H02부터 H05는 여러 기능이 공유하는 정책·데이터·연동 기준이다. H06의 미결정 항목을 해소하고 H07의 검수 시나리오로 완료 여부를 판단한다.

기존 일정·견적 금액은 이 문서에서 재산정하지 않았다. 범위가 바뀌는 상세 에디터·정책 설정 UI 등은 D15 합의 후 일정과 공수를 다시 검토한다.

## H03 주문 상태와 처리 보장

결제 완료는 결제 상태, 배송 준비 중은 배송 상태다. 기존 명세의 결제 완료 → 출고 대기라는 별도 단계 대신 승인 확인과 주문 확정이 완료되면 결제 완료 / 배송 대기로 표현하는 제안이다. 현재 status 1개를 실제 서버에서도 그대로 사용하는 전제가 아니다.

## 정상 주문 흐름

수량 선택 → 주문서 검증 → 서버 금액·판매상태·재고 확인 → 결제 요청 → 서버 승인 검증 → 주문과 주문상품 및 배송정보 확정 → 재고 1회 차감 → 완료 표시 → 출고 대상 추출 → 택배 접수 후 발송 처리.

## 정상 취소 흐름

취소 요청 → 소유권·권한·기한·발송 여부 검사 → 취소 진행 잠금 → PG 전액 취소 → 결과 확인 → 취소 상태 및 환불 기록 확정 → 재고 1회 복원. PG와 DB는 하나의 트랜잭션이 아니므로 중간 실패를 복구할 처리 기록이 필요하다.

## 중복과 동시 처리 및 복구

결제 요청과 취소·출고 작업에 고유 요청 키를 부여하고 중복 요청은 기존 결과를 반환한다. PG 거래번호와 주문 연결은 유일하게 관리한다. 중복 승인 콜백과 재시도는 재고를 추가 차감하지 않는다.

마지막 재고를 두 회원이 동시에 결제하는 경우 둘 다 승인된 채 한 주문을 잃지 않도록 임시 재고 예약과 만료·해제 또는 동등한 방식을 설계한다. 예약 기간·외부 승인 초과 시 보상 취소는 개발·PG 검토로 결정한다. 확인 중 결제는 조회 및 대사 후 복구하고 미해결은 운영 담당자에게 표시한다.

취소와 발송은 동일 주문에 대해 동시에 확정할 수 없다. 주문 버전 또는 서버 잠금으로 한 처리만 성공시킨다. 수동 재고 수정도 버전 검사로 결제 차감을 덮어쓰지 않는다.

## 외부 시스템 확인 자료

X01 기존 회원 인증: 세션 확인 방법·회원 고유 ID·로그인 성공 복귀·기존 제공 로그인수단. X02 PG: 상품 주문 승인·전액 취소·서명 검증·결과 조회·중복통지·테스트 계정. X03 우편번호: 주소 검색 실패 시 직접 입력. X04 택배사: 외부 조회 링크만 제공. X05 스토리지: 미디어 업로드·파일 URL·용량·삭제 기준.

## 오류 응답과 화면 처리 제안

오류는 code·사용자 메시지·fieldErrors 또는 상품별 오류·재시도 가능 여부·서버 요청 ID를 반환하는 제안이다. 인증 만료는 로그인 복귀, 권한 없음은 조회 불가, 재고 부족은 상품행, 가격·정책 변경은 새 총액 재확인, 버전 충돌은 최신값 확인, PG 결과 불명은 확인 중 상태로 연결한다.

## 검수 완료 조건

현재 문서 작성 단계에서는 검수를 실행하지 않았다. 정책 D항목을 확정하고 개발 후 각 TC에 결과·환경·증거·실패 이슈를 기록한다. 로그인·PG·권한·동시재고·취소출고 충돌·복구 시나리오 통과를 오픈 기준에 포함한다. 해상도별 결과는 실제 확인한 범위만 완료로 기록한다.

## 개발 착수와 인계 순서

회원·PG·기존 관리자 연동 자료 확인 → 정책·추가 범위 결정 → 데이터·API·처리 보장 설계 → 사용자 및 관리자 개발 → 시나리오 검수 → 운영 가이드 및 복구 담당 인계 → 합의된 오픈 절차 진행. 자동 알림 서비스 추가를 전제로 하지 않으며 운영 오류 확인 수단은 기존 관리자 또는 운영 도구와 연결해 정한다.

## 이번 개정의 핵심

화면 구조와 기능 및 검수 ID를 연결했다. 결제·배송·환불 상태를 분리하고, 미확정 배송비와 취소시간을 시연 기본값으로 명시했다. 견적에 포함된 노출순서의 구현 누락, 로그인과 본인 주문 권한 부재, 별도 수령인 입력 부재, 재고상한 누락, 관리자 취소의 시간 예외를 드러냈다.

상세 에디터·정책 설정 UI 등 시연 추가 기능은 개발 범위 재합의 대상으로 표시했다. 고정 저장·편집내용 보존·모바일 구매 영역·전체 상품 미리보기는 현재 구현 사실과 개선안을 분리했다. 기존 파일은 덮어쓰지 않고 v2로 생성했다.

## 확인 범위의 한계

이 문서는 저장소의 문서와 코드를 정적으로 대조한 기획 자료다. 고객사 원문 메일·실제 회원 서버·PG 설정·운영 DB·관리자 권한체계는 제공되지 않았다. 기존 명세가 메일 요구로 분류한 항목은 원문 요구를 재검증한 것으로 간주하지 않는다. 외부 URL과 서비스 이용 조건을 재검증하지 않았다.
